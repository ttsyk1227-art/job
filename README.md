# 生徒情報管理システム

高校向けの生徒情報管理システムです。生徒の個人写真・クラス名簿・部活動・日常記録(メモ)を
一元管理できます。Next.js (App Router) + Prisma + SQLite で構築しています。

## 主な機能

- **生徒名簿**: クラス・学年ごとの名簿表示、氏名/ふりがな/学籍番号での検索
- **個人写真**: 生徒ごとの写真アップロード・差し替え
- **部活動管理**: 部活動マスタ、部員の追加・削除、顧問の設定
- **日常記録・メモ**: 生活指導・健康・進路・保護者連絡などカテゴリ別の記録をタイムライン表示
- **権限管理**:
  - 管理者(ADMIN): 全データの閲覧・編集、クラス/教員アカウントの管理
  - 教員(STAFF): 自分が担任するクラス、または顧問を務める部活動に所属する生徒のみ閲覧・編集可能

## セットアップ

```bash
npm install
cp .env.example .env   # .env の AUTH_SECRET を openssl rand -base64 32 などで生成した値に変更してください
npx prisma migrate dev --name init
npm run db:seed        # サンプルデータ(教員・クラス・生徒・部活動)を投入
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開いてください。未ログインの場合は自動的に
ログイン画面へ移動します。

### サンプルログインアカウント(`npm run db:seed` 実行後)

| ロール | メールアドレス | パスワード |
| --- | --- | --- |
| 管理者 | admin@school.example.jp | password123 |
| 教員(担任) | yamada@school.example.jp | password123 |
| 教員(部活動顧問) | suzuki@school.example.jp | password123 |

本番運用時は必ずパスワードを変更し、`.env` の `AUTH_SECRET` を推測困難な値にしてください。

## 校内で複数の先生に使ってもらう(校内ネットワークでの運用)

「職員室の別のPCからもブラウザで使えるようにしたい」場合の手順です。常時電源が入っていて
校内LANに接続されている PC を1台「サーバー役」にし、他の先生はそのPCのIPアドレスに
ブラウザでアクセスする構成にします。特別なサーバー機材やクラウド契約は不要です。

### 1. サーバー役のPCを用意する

職員室の共有PCなど、日中(あるいは常時)電源が入っている1台を選びます。可能であれば
ネットワーク管理者に依頼し、その PC の IP アドレスが変わらないよう固定IPまたは
DHCP予約を設定してもらってください(変わってしまうと後述のアクセス用URLが変わります)。

### 2. Node.js をインストール

そのPCに [Node.js](https://nodejs.org/)(LTS版)をインストールします。Windows・Mac共通です。

### 3. プロジェクトを配置してセットアップ

```bash
git clone <このリポジトリのURL>
cd job
npm install
cp .env.example .env
```

`.env` を開き、`AUTH_SECRET` を推測されにくいランダムな文字列に変更してください
(`openssl rand -base64 32` などで生成できます。無ければ32文字以上の適当な文字列でも構いません)。

```bash
npx prisma migrate deploy
npm run db:seed     # 初回のみ。サンプルアカウントが入ります
npm run build
```

### 4. PM2 で常時起動させる

ターミナル/コマンドプロンプトを閉じてもサーバーが動き続けるよう、PM2 で管理します。

```bash
npm install -g pm2
pm2 start ecosystem.config.js
pm2 save
pm2 startup          # PC再起動後も自動起動させたい場合。表示される案内に従ってください
```

### 5. サーバー役PCのIPアドレスを確認する

- Windows: コマンドプロンプトで `ipconfig` を実行し、「IPv4 アドレス」を確認(例: `192.168.1.15`)
- Mac: 「システム設定」→「ネットワーク」、またはターミナルで `ifconfig`

### 6. 他の先生からアクセスする

同じ校内LANに繋がっているPC・タブレットのブラウザで、以下のURLを開いてもらいます。

```
http://<サーバー役PCのIPアドレス>:3000
```

例: `http://192.168.1.15:3000`。このURLをブックマークしてもらうと便利です。

### 7. Windowsのファイアウォール確認

初回起動時に「Windows セキュリティの重要な警告」が表示されたら、「プライベートネットワーク」
にチェックを入れて「アクセスを許可する」を選んでください。

### 8. 運用開始前の確認事項

- 管理者アカウントでログインし、実際の教員アカウントを「教員アカウント管理」画面から作成する
- サンプルアカウント(`admin@school.example.jp` など)はパスワードを変更するか使用をやめる
- `.env` の `AUTH_SECRET` を必ず変更する(手順3参照)
- `prisma/dev.db`(データベース)と `public/uploads/students`(生徒写真)は生徒の個人情報を
  含むため、定期的に外部媒体やNASへバックアップする(現時点では自動バックアップ機能はありません)

### 更新内容を反映するとき

```bash
pm2 restart student-management
```

## データベース

開発環境では SQLite (`prisma/dev.db`) を使用しています。本番運用でユーザー数・データ量が
増える場合は `prisma/schema.prisma` の `datasource` を PostgreSQL 等に変更してください。

## 個人情報の取り扱いについて

生徒の氏名・写真・日常記録は機微な個人情報です。本システムでは以下の対策を行っていますが、
実運用前に学校の個人情報保護方針に沿って追加の対策を検討してください。

- ロールベースのアクセス制御(担任・顧問は自分の関係する生徒のみ閲覧可能)
- パスワードは bcrypt でハッシュ化して保存
- アップロードされた写真・SQLite データベースファイルは Git 管理対象外(`.gitignore` 済み)
- セッションは 12 時間で自動的に失効

追加で検討すべき事項の例:

- 通信の HTTPS 化(本番デプロイ時にリバースプロキシ等で設定)
- 操作ログ(誰がいつ生徒情報を閲覧・編集したか)の記録
- 卒業・退学した生徒データの保管期間ルールと削除フロー
- パスワード変更・リセット機能(現バージョンには未実装)
